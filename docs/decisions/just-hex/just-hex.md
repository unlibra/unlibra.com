# Just HEX の判断ログ

新しいアプリ Just HEX の追加（2026-10-25、ユーザーの指示）。親が直接実装し、レビューは省いた。build、lint、format:check、`npm test`、`npm run test:e2e` で確かめた。

ハッシュの URL（`/hex/#ffffff`）を色コードに見立てて、その色で画面全体を塗るアプリ。

## JH-1 URL（ユーザーの決定）

- トップは `/hex`。ほかのツールのように `/lab` の下には置かず、ルート直下にした。
- 色の画面の URL は `/hex/#ffffff`（2026-10-25 のユーザーの指示で、スラッシュ入りに変えた。初めは `/hex#ffffff`）。サイトの規則（末尾のスラッシュを付けない）の例外で、色の画面のときだけアドレスバーに `/hex/` を出す。
- 静的アセットは `/hex/` を `/hex` にリダイレクトするので、`/hex/` は Worker（`run_worker_first` の `/hex/*` に入る）がリダイレクトせずに `/hex` のページをそのまま返す。canonical は `/hex` のまま。
- ページはアドレスバーをそろえる：色があれば `/hex/#ffffff`（`/hex#FFF` も `/hex/#ffffff` になる）、色がなければ `/hex`。フォームから色に移るときは `pushState` で `/hex/#ffffff` にし、ブラウザの「戻る」でトップの `/hex` に戻る。
- 既存のツールをルート直下に移すかどうかは、このブランチでは扱わない（ユーザーが迷っている点。移すなら、リダイレクトを足す作業として別に行う）。

## JH-2 言語（ユーザーの決定）

英語だけのページ。最初は日本語だけと答えたあと、ユーザーが英語だけに訂正した。URL は `/en/` を付けない `/hex` で、`<html lang="en">`、ヘッダーとフッターも英語にした。日本語版がないので、言語の切り替えと hreflang はない。

文言はツールの文言（`src/tools/messages/`、日本語と英語の両方が要る）には入れず、`src/tools/just-hex/messages.ts` に置いた。

## JH-3 色ごとの OGP と Worker（ユーザーの決定）

ハッシュはサーバーに送られないので、`/hex#ffffff` のままでは色ごとの OGP を作れない。そこで、シェアに使う URL はパスの形 `/hex/ffffff` にし、Worker がその色の OGP を付けて返す。ユーザーは構成の変更と費用を聞いたうえで、Worker で作る方を選んだ。

- `wrangler.jsonc` に `main`（`worker/index.ts`）と `assets.run_worker_first: ["/hex/*"]`、`assets.binding: "ASSETS"` を足した。これまでの「静的アセットだけ、Worker のスクリプトなし」の構成が変わる。`tests/build.test.js` の A9 もこれに合わせた。
- Worker が動くのは `/hex/*` だけ。`/hex` を含むほかのリクエストは、今までどおり静的アセットとして配信し、Worker を通らない（静的アセットへのリクエストは無料で上限もない。2026-10-25 に Cloudflare の文書で確かめた）。
- Free プランなら1日10万リクエスト、1リクエストの CPU 時間 10ms まで。上限を超えると `run_worker_first` のパスは 429 になる（同じく文書で確かめた）。ほかのページには影響しない。どのプランかは確かめていない（要確認）。
- `/hex/ffffff`：Worker が静的アセットの `/hex` を取り、HTMLRewriter で `<title>`、description、canonical、`og:*`、`twitter:*` を色のものに書き換える。画像は `/hex/ffffff.png`。
- `/hex/ffffff.png`：1200×630 の単色の PNG。1ピクセル1ビットのパレット PNG で、画素の圧縮データはどの色でも同じなので、1つの isolate で1回だけ作る。色ごとに作るのはパレット（3バイトと CRC）だけで、CPU 時間はほぼかからない。中身は URL で決まるので `Cache-Control: public, max-age=31536000, immutable`。
- `FFF` や `FF8800` など、ほかの書き方の色は、小文字6桁の形（`/hex/ffffff`）に 301 で移す。色でないもの（`/hex/zzz` など）は静的アセットに回し、404 になる。
- ブラウザで `/hex/ffffff` を開くと、ページの最初のスクリプトがアドレスバーを `/hex/#ffffff` に書き換える（ユーザーの「表示はハッシュ、内部で URL を持つ」）。
- 制限：X に色のカードが出るのは、メニューの「Share on X」から投稿したとき（URL は `/hex/ffffff`）だけ。アドレスバーの `/hex/#ffffff` をそのまま貼ると、サイト共通の OGP になる。
- Worker の型は `wrangler types worker/worker-configuration.d.ts` で作り、リポジトリに入れた（`wrangler.jsonc` を変えたら作り直す）。ルートの tsconfig は `worker/` を外し、`worker/tsconfig.json` で型を確かめる。`npm run build` は `tsc -p worker` も行う。
- 要確認：Cloudflare Web Analytics の自動挿入が、Worker が返す `/hex/ffffff` の HTML にも効くか。`_headers` のヘッダーは、Worker が `ASSETS` から取った HTML には付く（ローカルの `wrangler dev` で確かめた）。Worker が自分で作る PNG と 301 には付かない。

## JH-4 シェアのボタン（ユーザーの指示、ui-revise 3 の例外）

ui-revise 3 で「スポンサー、X シェア、シェアのボタンを全ページで廃止」したが、Just HEX の色の画面のドックの「Share on X」は、今回のユーザーの指示で置く。例外はこのメニューだけで、`tests/portfolio.test.js` の ui-revise 3 のテストは、`/hex` のドック（`[data-hex-dock]`）だけを除いて、ほかはそのまま確かめる。

## JH-5 画面の作り

ユーザーの指示：色の画面にはヘッダーもフッターも出さない。Just HEX のトップに戻る、色コードをコピーする、X にシェアする、ができる（初めはクリックで出るメニュー。JH-8 でドックに置き換えた）。トップはヘッダーとフッター付きで、色コードの入力欄と移動のボタンを置く。

以下は親の判断（案）。変えたいときはこのログを直す。

- トップと色の画面は同じページ（`src/pages/hex.astro`）。色の画面は `BaseLayout` の新しい `screen` スロットに置き、ハッシュが色のときだけ見せる。レイアウト（`[data-layout]`）は隠す。
- ページの `<head>` の最初のスクリプト（`BaseLayout` の新しい `head` スロット）が、描く前にハッシュを読んで `<html data-hex>` を付けるので、ヘッダーが一瞬出ることはない。ハッシュを読む規則は `src/tools/just-hex/hex.ts` の `hexPattern` 1つで、このスクリプトにも渡す。
- 色コードは 3桁か6桁の16進数で、`#` はあってもなくてもよく、大文字でもよい。表示とアドレスバーは小文字6桁にそろえる（`#F80` → `#ff8800`）。8桁（透明度付き）は受け付けない。
- 色でないハッシュ（`#nope` など）は、トップを出し、入力欄にその文字を入れる（エラーは JH-7）。
- X の投稿の文は「Just HEX | URL」（ユーザーの指示。区切りの文字は、ページの題やシェアの文で最もよく使われる `|` を親が選んだ。サイトの `<title>` の区切りは `-` のまま）。
- タブの題は色の画面で「#ffffff - Just HEX - unlibra」にする。
- 色ごとのページ（1677万通り）は検索に載せる意味がないので、`/hex/ffffff` には `noindex` を付けた。`/hex` はサイトマップに載り、検索の対象にする。
- ライセンス：ほかのツールと同じ MIT にした（ユーザーの決定、JH-11）。初めは「All rights reserved」の場所（`src/pages`、`src/config`、`src/messages`、`worker/`）に置いていた。
- トップの Apps のセクションに載せた（JH-11）。

## JH-7 トップの見た目（ユーザーの指示、2026-10-25）

ユーザーの指示：Just HEX はほかのツールと印象をそろえなくてよい。アート寄りで、立ち位置は廃止したイロマイドに近い。説明は全部なくし、タイトル、色コードの入力欄、移動のボタンだけにする。説明的でなく感覚的に。ヒントは入力欄のプレースホルダーだけ（または、初めからランダムな色コードを入れておく）。パンくずの「Home」に「(Japanese)」は付けない（そのあと、パンくずごと消した。下の最後の項目）。

以下は親の判断（案）。

- 説明文はページから消した。meta description（「One color. The whole screen.」）と構造化データは、検索とシェアのために残した。
- タイトル「Just HEX」は等幅（Geist Mono 500）で、48px（640px 以上は 72px）。ページの h1 は 28px という規則（DESIGN.md 2.2、`consistency.spec.js`）の例外にした。
- 入力欄は等幅 30px で、下線だけの欄。プレースホルダーは `#000000`。開いたときに、ランダムな色コードが入っている（両方を使った）。ラベル「Color code」は読み上げだけ。等幅は 14〜16px という規則（DESIGN.md 2.2）の例外。
- 移動のボタンは丸い矢印のボタン（Tabler の arrow-right。名前は「Show」）。ボタンの地は入力欄の色そのもので、矢印は色の明るさで黒か白にする。色コードでないときは地がなくなり、矢印だけになる。縁はどの色でも付けない（ユーザーの決定：背景に近い色でボタンの地が溶けても、矢印が見えるので問題ない。初めは薄い縁と、色コードでないときの破線の縁があった）。
- 色コードでないまま押すと、入力欄が少し揺れ（動きを減らす設定では揺れない）、`aria-invalid` を付け、「Not a color code.」を読み上げだけに伝える。画面にエラーの文は出さない。
- 色の画面からトップに戻ると、入力欄にはその色が入っている。
- パンくずは、ユーザーの指示で消した（2026-10-25）。画面のパンくずも、構造化データの BreadcrumbList もない。ほかのツールのページにはある（`tests/tools.test.js` の E3）が、Just HEX はツールではないので、そろえない。トップへはヘッダーのロゴで戻れる。

## JH-8 色の画面のドック（ユーザーの決定、2026-10-25）

クリックで出るメニューは、知らなければ気付かないので、ユーザーの案で画面の下の小さなドックに置き換えた。ドックには「Back to Just HEX」「Copy #ffffff」「Share on X」の3つのアイコンのボタンを置く。

挙動（ユーザーが選んだもの）：

- マウスを動かすと出て、2 秒止まると消える。ドックの上にポインターがある間と、キーボードのフォーカスがある間は消えない（Tab でドックに入ると出る）。マウスで押したボタンにもフォーカスは残るが、それでは消えないままにはしない（ユーザーの指摘。`:focus-visible` のときだけ残す。`blur()` でフォーカスを外す方法は、キーボードで押したときにもフォーカスを失うので選ばなかった）。
- 色の画面に来たとき（開いたとき、トップから移ったとき）に、3 秒だけ出す。初めての人がドックに気付けるように。
- ドックが消えている間は、カーソルも隠す。消えているドックはクリックを受けない。
- タッチの端末では、色をタップすると出て 3 秒で消え、出ている間にタップすると消える。

全画面表示のボタンは足さない。パソコンはブラウザの機能（F11 など）で全画面にできる。Android の Chrome は Fullscreen API に対応しているが、iPhone の Safari は caniuse で「一部対応」とされ、動画以外の要素を全画面にできるかは確かめられなかった（要確認）。ユーザーは「パソコンだけならなくていい」とした。

以下は親の判断（案）。

- 見た目：画面の下の中央に、角の丸い半透明のガラス（60%、ぼかし）。縁はなく、弱い影（Tailwind の `shadow-md` を黒 10% で）を付ける（どちらもユーザーの指示）。内側の余白は上下左右とも 8px（ユーザーの指示。初めは 4px、次に左右だけ 8px にしたが、上下が違うと違和感があるため）。サイトのテーマには従わない。
- ドックの色は背景の色の反対（ユーザーの指示）。明るい色の上では黒 60% に白のアイコン、暗い色の上では白 60% に gray-900 のアイコン。明るいか暗いかは、黒と白のどちらがその色とのコントラストが高いか（WCAG の相対輝度で約 0.179 が境）で決める。トップの移動のボタンの矢印と同じ判定（`src/tools/just-hex/hex.ts` の `toneOf`）。
- ボタンは 44px（DESIGN.md 5.4）で、Tabler の palette、copy、brand-x（戻るボタンは初め arrow-left。ユーザーが arrow-left、layout-grid、palette、home から palette を選んだ。戻り先が色を選ぶ場所だと分かるため）。読み上げの名前とマウスのツールチップ（`title`）は「Back to Just HEX」「Copy #ffffff」「Share on X」。コピーすると 2 秒間チェックのアイコンになり、「Copied!」を読み上げに伝える。
- 出し入れはフェード（0.2 秒）だけで、動きはない（動きを減らす設定でも同じ）。
- 名前の表記は「Just HEX」のまま（ユーザーの決定）。

## JH-9 トップの背景と、色が広がる演出（ユーザーが試すと決めた案、2026-10-25）

ユーザーは、トップを真っ白のままにするか背景で遊ぶかを迷っていた。親の案（入力中の色のぼんやりした光と、「Show」で色が広がる演出）を、ユーザーが試すと決めた。採用するかは、見てから決める（未決）。

- （廃止）光：タイトルと入力欄の後ろに、入力中の色の大きな円を置く（中心から透明に向かう放射状のグラデーション、ぼかし 40px）。濃さはライトで 45%、ダークで 30% にし、タイトルと入力欄の文字のコントラストを保つ。大きさは 40rem と画面の幅と高さの 60% のうち小さい方で、横にはみ出さない（375px で横のスクロールが出ない）。
- 色は、ステージ（`[data-hex-stage]`）の `--swatch` をボタンが使う。`@property` で色として登録し、入力が変わると 0.4 秒で色が移る。色コードでないときは透明に消える。
- 広がる演出：「Show」を押すと、ボタンの位置から、その色の円が画面を覆うまで 0.4 秒で広がり（ユーザーの指示で 0.6 秒から速めた）、そのあと色の画面になる。動きを減らす設定では広がらず、すぐに色の画面にする。広がる層は読み上げから隠し、クリックも受けない。色の画面が下に描かれてから消す。
- 縮む演出（ユーザーの指示）：色の画面からトップに戻るとき（ドックの戻るボタン、ブラウザの「戻る」）、色が画面いっぱいからトップのボタンに向かって 0.4 秒で縮む。層を被せたままトップを描き、ページの先頭までスクロールしてからボタンの位置を測る。動きを減らす設定では縮まない。
- （廃止）光の動き（ユーザーが親の案を選んだ）：普段は動かさない。「Show」で色がボタンから広がるのと同時に、光がボタンへ吸い込まれて消える（同じ 0.4 秒）。戻るときは、色が縮むのと同時に、光がボタンから出てきて元に戻る。光は色の層の下にある。色が広がる起点は、光ではなくボタンのまま（ユーザーの決定。押したところから広がる方が分かりやすく、縮む先とも対になる）。
- ドックの戻るボタンは、同じページの中で戻る（読み込み直さない）。そのため入力欄には戻った色が残る（ユーザーの指示）。「Show」で来たときは履歴の「戻る」と同じにして履歴を増やさず、共有の URL などで直接来たときは `/hex` を新しい履歴にする。`href="/hex"` のリンクのままなので、Ctrl＋クリックなどで新しいタブに開ける。

ユーザーはこの案を見て「いい感じ」とした。

その後、ユーザーの判断で光を廃止した（2026-10-25。気が散るため）。光と、その吸い込まれる・出てくる動きはなくなり、色が広がる・縮む演出と、ボタンの色だけが残る。トップの背景は元の白（ダークでは暗い背景）に戻った。

## JH-10 ロゴのクレジット（ユーザーの指示、2026-10-25）

ユーザーの方針で、グラフィック素材はクレジットのページに書く。ほかのサービスのロゴのうち、ヒーローの GitHub マーク（GitHub の公式のマーク）と、Just HEX のシェアボタンの X ロゴを、クレジットの「グラフィック素材」に「ロゴ」として足した（「〇〇：〇〇 の商標です」）。値は `src/config/credits.ts` の `trademarks`。

- X ロゴのアイコンは X の公式のファイルではなく、Tabler Icons の `brand-x`（MIT、クレジット済み）。形は X Corp. の商標のロゴ。
- そのあとユーザーが「Tabler Icons が描いたものはクレジットに含めない」と決め、X ロゴをクレジットから外した。GitHub マークは Tabler ではなく GitHub の公式のマーク（`GitHubIcon.astro`）なので残した。
- `LICENSE` の第3節（このライセンスの対象外）にも、X ロゴ（`BrandXIcon.astro`）を GitHub マークと並べて書いた。
- npm と PyPI のロゴ（Libraries のアイコン）も第3節にあるが、クレジットには足していない（ユーザーが挙げたのは GitHub と X だけ）。

## JH-11 Apps 欄、アイコン、ライセンス（ユーザーの指示、2026-10-25）

- Just HEX をトップの Apps 欄に載せた。Apps の先頭で、大カード（SPOTLIGHT）にする（`featured: true`。大カードは DIY Keyboards の fosty natural と合わせて2枚になった）。リンクは `/hex`、ボタンはほかのアプリと同じ「アプリを開く」。
- 紹介文（親が書いた）：「画面いっぱいに、ただ一色。好きな色を#のあとに書いて、そのまま誰かに届けよう。」（`src/messages/ja.ts` の `works["just-hex"]`）。初めは説明的な文だったが、ユーザーの指示で、説明的でなくキャッチーな文にした（JH-13）。
- アプリのアイコンを、DiceBear の「Blobs」（CC0 1.0、DiceBear のスタイルの一覧で確かめた）にした。seed は（初めは）Just HEX が `just-hex`、ほかはツールの ID（`svg-optimizer`、`favicon-generator`、`password-generator`）。HTTP API（`https://api.dicebear.com/10.x/blobs/svg?seed=…`）で作り、生成されたままの SVG（DiceBear のメタデータ付き）を `src/assets/tools/` に置いた。seed で色が決まり、Just HEX とパスワードジェネレーターはどちらもオレンジ系になった。
- Blobs は背景（正方形の色）を持つので、アイコンの後ろの円（`sora-deep` の 70%）をなくした（ユーザーの指示「背景透過をやめて背景に使っていた円を削除」）。アイコンの形は円のまま（ui-revise5 6 の「Apps のアイコンは円」）で、Blobs の正方形を円に切り抜いている。ユーザーが見て、丸のままに決めた。
- 前のアイコン（DiceBear の「Shapes」）はもう使わないので、`LICENSE` 第2節とクレジットの見出しを `DiceBear "Blobs" and "Planets"` にし、`just-hex.svg` を一覧に足した。
- ライセンス：ほかのツールと同じ MIT にした（ユーザーの指示）。`LICENSE` 第1節で MIT のディレクトリは `src/tools/` なので、Just HEX のロジックを `src/tools/just-hex/` に移した：`hex.ts`（色コード）、`messages.ts`（文言）、`og-image.ts`（OGP の PNG）、`just-hex.ts`（ページの動き。サイトの URL と名前は引数で受け取り、MIT の外を読み込まない）。ページの作り（`src/pages/hex.astro`）と Worker（`worker/index.ts`）は、ほかのツールのページと同じく MIT の外のまま。MIT のコードが MIT の外を読み込まないことは eslint の検査で確かめている。

## JH-12 等幅フォントを DM Mono に（ユーザーの指示、2026-10-25）

## JH-13 トップの登場、紹介文、アイコン、大カードのアイコンの大きさ（ユーザーの指示、2026-10-25）

## JH-14 フェード、紹介文、抽象画のアイコン、大カードの画像、本番チェック（ユーザーの指示、2026-10-25）

- トップの登場は、下から浮かぶ動き（JH-13）をやめ、その場でふわっと浮き出るフェードにした：透明でぼけた状態から 0.5 秒で、タイトル・入力欄・矢印が一度に現れる（ユーザーの指示。初めは 1 秒で 0.15 秒ずつずらし、次に 0.3 秒にした）。スクリプトが最初のランダムな色を入れ終えてから現れる（それまでは見せない）。ボタンの色が、現れたあとに遅れて付くことがないように。カーブは easeOutCubic（`cubic-bezier(0.33, 1, 0.68, 1)`。ユーザーが選んだ。初めは ease-out）。動きを減らす設定では現れ方の演出をしない。色の画面から戻ったときもしない。
- Apps 欄の紹介文は、ユーザーが書いた「ただ、一色に。カラーコードを入力すると、画面いっぱいにその色が広がる小さなWebアプリ。好きな色を、URLひとつで誰かに届けられます。」（2026-10-26。その前は同じくユーザーの「カラーコードで、世界を一色に。好きな色を誰かに届けよう。」）。一覧のカードの紹介文は 1280px で2〜3行という規則（ui-revise6 2）は一覧のカードのためのものとして、大カードの Just HEX は対象から外したまま。
- アイコンを、抽象画にした（ユーザーの指示「もっと抽象的に、アートっぽく」）。深い赤の地に、縁をぼかした橙・赤・黄の色の面を重ね、細かい粒子を載せた（ロスコの色面のような絵）。「#」はなくした。円に切り抜かれても、4:3 の枠いっぱいでも成り立つよう、色の面は真ん中に寄せた。JH-13 のコーラルと「#」のアイコンは置き換えた。このあとユーザーが、アイコンの絵はほかの人に描いてもらうと決めた。届くまでは、この抽象画を仮に使う。
- 大カード（SPOTLIGHT）では、アプリのアイコンを円にせず、写真と同じく枠（4:3）いっぱいに広げる（JH-13 の「高さの 60%」は置き換えた）。一覧のカードでは今までどおり円。
- 本番チェック（`npm run check:prod`、毎日の production-check のワークフローでも動く）に、Just HEX の共有 URL（`/hex/ff5a36`）の OGP（`og:url`、`og:image`、`twitter:image`）と、その OGP 画像（`/hex/ff5a36.png` が PNG で返ること）の確認を足した（ユーザーの指示）。

## JH-15 Just HEX のロゴ（ユーザーの決定、2026-10-26）

ユーザーがロゴを決めた：青い背景の真ん中に白い丸。コンセプトは「Just」。JH-14 の抽象画（仮）を置き換えた。
