## DN-1 フッターの寄付リンク（ユーザーの決定）

フッターの「寄付・支援」は OFUSE（`https://ofuse.me/unlibra`）ではなく、サイト内の `/donate` に飛ぶ。サイト内のページなので同じタブで開く。OFUSE へのリンクはサイトからなくした（`site.links.sponsor` を消した）。英語のページのラベルは、ほかの日本語だけのページと同じく「Donate & Support (Japanese)」にした。

## DN-2 寄付の受け取り方（ユーザーの決定）

寄付は Amazon eギフトカードで受け取る。受取人のアドレスは `gift@unlibra.com`。リンクのボタンは amazon.co.jp の Amazon eギフトカードの商品ページ（`/dp/B06X1GVMW7`）に飛ぶ。ユーザーが選んだのは「Eメールタイプ」で、Amazon での今の名前は「Amazon eギフトカード」（2026-10-24 に商品ページで確かめた）。ページの文言はユーザーの指定で「Amazonギフトカード」にした。値は `src/config/site.ts` の `site.donation` に置いた。

商品ページはユーザーの指定で、デザイン「Amazon スマイル」の `B06X1GVMW7`（初めは「Amazonロゴ - クラシック」の `B004N3APGO` だった）。

リンクには `?gpo=500` を付け、Amazon のページで金額に ¥500 が入った状態で開く。`gpo` はユーザーが示したパラメータで、2026-10-24 に `B06X1GVMW7` の商品ページの金額の欄が ¥500 になることを確かめた。金額は Amazon のページで変えられるので、ページの「金額は自由です」はそのままにした。

初期値の ¥500 は、ユーザーの「日本で最も一般的な寄付金額に合わせる」という指示による。1回の寄付の金額の分布を直接示す統計は見つからなかった。近い調査の中で、1回の少額の応援として最も多かったのが「500円以下」（消費者庁のコラム。ライブ配信の投げ銭で、2018年の調査）だったので ¥500 にした。寄付白書の中央値の1万円は、1年間の寄付の合計なので使わなかった。

## DN-3 ページの作り

- 日本語だけのページで、クレジット・プライバシーポリシーと同じ `MarkdownLayout`。h1「寄付・支援」、案内の段落、アドレスとコピーのボタン、Amazon のボタンの順。
- アドレスとコピーのボタンは、パスワードジェネレーターと同じ作りにした（ユーザーの指示「統一して」）。枠（白、枠線 gray-200、ダークは `atom-one-dark-light` と gray-600、角丸 `rounded-lg`）の中に等幅のアドレスを置き、右端に「コピー」のボタンを置く。ボタンはパスワードジェネレーターから `src/components/ui/copy-button.tsx` の `CopyButton` に切り出し、両方で使う。結果の出し方は DN-6。
- ボタンの読み上げの名前は「メールアドレスをクリップボードにコピー」（パスワードジェネレーターの「パスワードをクリップボードにコピー」に合わせた。見えている「コピー」を含む）。
- ボタンは React の島（`src/components/donate/donate-copy-button.tsx`）で、寄付ページでも React を読み込む。
- Amazon のボタンは新しいタブで開くリンク。色は `primary` の地に白（4.5:1）、ホバーは `primary-dark`。Markdown のページのリンクの色（下線つき）を当てないよう、`MarkdownLayout` のリンクの規則を `a:not([data-button])` にした。
- Amazon のボタンの色の変化の動きは `motion-safe:` にし、動きを減らす設定では止める（DESIGN.md 5.6）。
- アイコンは既存の `ArrowUpRightIcon` だけを使い、新しいアイコンは足していない。

## DN-4 アドレスのスパム対策（ユーザーの決定）

Cloudflare の Scrape Shield（Email Address Obfuscation）で隠す。設定はユーザーが Cloudflare のダッシュボードで ON にする（コードの変更ではない）。

- Cloudflare は HTML の文字のアドレスを隠し、属性（`<a>` の `href` を除く）はそのまま残す。そこで、アドレスはページの文字（`[data-donate-email]`）にだけ書き、属性には書かない。コピーのボタンの島にもアドレスを渡さない（島の props は属性に入るため）。ボタンは押したときに `[data-donate-email]` の文字を読む。
- Cloudflare のスクリプトがアドレスを戻す前の文字（アドレスの形でないもの）は、コピーせずに「コピーに失敗しました」を出す。
- 要確認：Workers の静的アセットで配信している HTML に効くかは、Cloudflare の文書に書かれていない。ON にした後、本番の `/donate` の HTML でアドレスが隠れていることを確かめる。

## DN-6 ボタンの色と文言（ユーザーの決定）

- sky の色は、ツールのプライバシー注記（情報の色）を除いて、サイト全体で `primary` にした。スライダーも `primary`。`link` はリンクにだけ使う。
- 色の名前を役割で分けた。空色の2色は飾りの色として `sora`（#a0d8ef）と `sora-deep`（#4d9fd6、元の `primary`）にし、ヒーローの背景と Apps のアイコンの丸にだけ使う。ダークのリンクは `link-dark`（値は `sora` と同じ）にした。`primary-light` はなくした。
- UI の色の `primary` は、ボタンの白の文字が 4.5:1（DESIGN.md 3.1）になるよう、`sora-deep` を OKLCH で暗くした #277db2。ホバーとチェックボックスの `primary-dark` は、同じ幅だけさらに暗くした #02689c（6.06:1）。メニューの選択中の背景は `primary` の 10%。一度は `primary` を 3:1（#4a9cd3）にしたが、ボタンの文字は 16px で大きな文字ではなく、AA の 4.5:1 が要るのでやめた。
- ヒーローの背景は元の色（`sora`、`sora-deep`）のままなので、キャッチコピーの「昼」の色は測り直していない。
- コピーのボタンはトーストをやめ、押すと 2 秒間「完了」（英語は「Copied!」）とチェックのアイコンに変わる。「コピー」と「完了」は同じセルに重ね、幅は長い方に固定する。結果は画面に出ない `role="status"` で読み上げに伝える。失敗したときは読み上げだけで伝える。

## DN-7 キャッチコピーの「昼」の色（ユーザーの決定）

`catch-day` を #d25f00 から、元にした伝統色「黄丹」そのものの #ee7800 にした。ヒーローの背景に対して 3:1 を下回る（約 2.3:1）が、ここは可読性より見た目が大事な場所なので例外にした（DESIGN.md 3.1）。色は飾りで、意味は文字で伝わる。`colors.spec.js` の 3:1 の確認は「夜」だけに残した。
